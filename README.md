## Что делает бот

Сценарий пользователя:

1. Пользователь пишет `/start` — видит главное меню с 3 кнопками:
   - **❓ Задать вопрос виртуальному помощнику** — переходит в режим Q&A.
   - **📞 Связаться с менеджером** — выдаёт контакты (Telegram, e-mail, телефон с добавочным).
   - **📋 Часто задаваемые вопросы** — ссылка на полный FAQ на Яндекс.Диске.
2. В режиме Q&A любой текст пользователя уходит в OpenAI с системным промптом, включающим весь FAQ-документ. Модель отвечает только на основе FAQ; если не нашла — возвращает фразу-маркер «нет данных по этому вопросу».
3. После ответа появляются кнопки «👍 Полезно / 👎 Не помогло». Оценка пишется в CSV и пересылается админам.
4. Если бот не смог ответить, он дополнительно подбирает **до 3 близких по смыслу вопросов** из FAQ (отдельный вызов модели, JSON-режим) и предлагает их пользователю с фразой «Возможно, вы хотели спросить:».
5. Все вопросы, ответы и оценки логируются в `questions_log.csv` и **дублируются в Telegram двум админам** (Школа коммуникаций + куратор проекта).

## Архитектура

```
Пользователь Telegram
       │
       ▼
 python-telegram-bot v21 (long polling)
       │
       ├─► OpenAI Chat Completions (gpt-5.2)
       │       ├─ ask_question()           — основной ответ (system prompt = FAQ)
       │       └─ suggest_reformulations() — JSON-подсказки переформулировок
       │
       ├─► CSV-лог  questions_log.csv
       └─► Уведомления в Telegram админам (ADMIN_CHAT_ID, ADMIN_CHAT_ID_2)
```

Ключевые компоненты в `bot.py`:

| Сущность | Назначение |
|---|---|
| `load_document()` | Парсит `.docx` (текст + таблицы + гиперссылки) в строку для system prompt. |
| `SYSTEM_PROMPT` | Инструкция модели + содержимое FAQ. Запрещает markdown и выход за рамки FAQ. |
| `ask_question()` | Основной вызов OpenAI с историей последних 5 Q&A пользователя. |
| `strip_markdown()` | Чистит остаточные `**bold**`, `*italic*`, `# headings` (бот шлёт plain text). |
| `extract_faq_questions()` | Достаёт из текста FAQ список вопросов (строки, начинающиеся с `В:`). |
| `suggest_reformulations()` | Если ответа нет — спрашивает модель, какие из 43 вопросов FAQ ближе всего к запросу. JSON-режим. |
| `notify_admin()` | Шлёт вопрос/ответ в Telegram обоим админам. |
| `log_question()` / `update_rating()` | CSV-лог: timestamp, user, вопрос, ответ, оценка. |

## Конфигурация (.env)

На сервере лежит в `/opt/bot/.env`. В репозитории шаблон — `Чат бот/.env.example`.

| Переменная | Назначение | Прод-значение |
|---|---|---|
| `TELEGRAM_TOKEN` | Токен Telegram-бота от @BotFather | задан |
| `OPENAI_API_KEY` | Ключ OpenAI (используется только для chat.completions) | задан |
| `OPENAI_MODEL` | Какую модель использовать | `gpt-5.2` |
| `DOCUMENT_PATH` | Путь к FAQ-файлу (относительно WorkingDir) | `FAQ_DPO_HSE_v5.docx` |
| `ADMIN_CHAT_ID` | Telegram chat_id первого админа (получает уведомления) | `7813576476` (`@economy_tutor`) |
| `ADMIN_CHAT_ID_2` | Второй админ — дубликат уведомлений в Школу коммуникаций | `6867443104` (`@dposchoolcomm`) |
| `LOG_FILE` | Путь к CSV-логу | `questions_log.csv` |

> **Чтобы добавить ещё одного админа:** нужен его **числовой Telegram chat_id**. Бот не умеет
> отправлять личные сообщения по `@username`. Простой способ узнать ID — попросить человека
> написать `/start` боту `@userinfobot`, тот вернёт `id`.

## Локальный запуск

```bash
# 1. Установить зависимости (рекомендуется venv)
python -m venv venv
source venv/bin/activate   # Windows: venv\Scripts\activate
pip install -r "Чат бот/requirements.txt"

# 2. Скопировать .env.example в .env и заполнить токены
cp "Чат бот/.env.example" .env

# 3. Запустить (FAQ-файл должен лежать рядом)
python bot.py
```

Зависимости (`Чат бот/requirements.txt`):

- `python-telegram-bot==21.6` — Telegram SDK
- `openai>=1.68.0` — клиент OpenAI
- `python-dotenv==1.0.1` — чтение `.env`
- `python-docx>=1.0` — парсинг `.docx`
- `lxml>=4.9` — нужен `python-docx` для гиперссылок

## Деплой и обслуживание на сервере

**Доступ:** SSH `root@206.251.48.91` (пароль — у владельца проекта).

**Расположение:**
```
/opt/bot/
├── bot.py                      # ← код
├── FAQ_DPO_HSE_v5.docx         # ← FAQ
├── .env                        # ← секреты и настройки
├── venv/                       # Python venv
├── questions_log.csv           # CSV-лог
└── .git/                       # (исторический; деплой через SCP, не git pull)
```

**Сервис управляется systemd:** unit-файл `/etc/systemd/system/faqbot.service`

```ini
[Unit]
Description=FAQ DPO HSE Telegram Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/bot
ExecStart=/opt/bot/venv/bin/python3 bot.py
Restart=always
RestartSec=5
EnvironmentFile=/opt/bot/.env

[Install]
WantedBy=multi-user.target
```

### Базовые команды

```bash
# Статус
systemctl status faqbot

# Перезапуск (после правок кода или .env)
systemctl restart faqbot

# Стоп / старт
systemctl stop faqbot
systemctl start faqbot

# Логи последних N строк
journalctl -u faqbot -n 50 --no-pager

# Логи в реальном времени
journalctl -u faqbot -f
```

При запуске бот пишет в журнал:

Если этих строк нет — что-то не так с FAQ-файлом или с токенами.

## Типовые задачи поддержки

### 1. Обновить FAQ-документ

Источник истины — `FAQ_DPO_HSE_v5.docx`. Структура каждого блока:

```
9. Удостоверение и итоговые документы          ← заголовок раздела
В: Как получить удостоверение?                  ← вопрос (префикс "В:")
О: После успешного прохождения ...              ← ответ (префикс "О:")
```

Префикс `В: ` обязателен — по нему функция `extract_faq_questions()` собирает список 43 вопросов для подсказок переформулировок. Без префикса вопрос работать будет, но не появится в подсказках.

Шаги:
1. Отредактировать `FAQ_DPO_HSE_v5.docx` локально (Word / LibreOffice / `python-docx`).
2. Закоммитить в git: `git add FAQ_DPO_HSE_v5.docx && git commit -m "Update FAQ" && git push`.
3. Залить на сервер: `scp FAQ_DPO_HSE_v5.docx root@206.251.48.91:/opt/bot/`.
4. Перезапустить: `ssh root@206.251.48.91 systemctl restart faqbot`.
5. Проверить в логах: `Извлечено вопросов из FAQ: N` (число должно совпасть с количеством `В:` в файле).

### 2. Поменять текст/ссылку в коде (телефон, e-mail, FAQ-URL)

Файл — `bot.py`. Ключевые места:
- `MANAGER_PHONES_TEXT` (~стр. 43) — телефоны для fallback-сообщения «не нашёл ответ».
- Обработчик `BTN_MANAGER` (~стр. 495) — текст кнопки «Связаться с менеджером».
- Обработчик `BTN_FAQ` — текст кнопки «Часто задаваемые вопросы» (тут ссылка на Я.Диск).
- `start_handler` — приветствие в `/start`.

После правки: коммит → push → `scp bot.py root@206.251.48.91:/opt/bot/` → `systemctl restart faqbot`.

### 3. Поменять модель OpenAI

Редактируем `/opt/bot/.env`:
```
OPENAI_MODEL=gpt-5.2
```
Перезапускаем сервис. Дефолт в коде (`bot.py`, переменная `OPENAI_MODEL`) — `gpt-5.2`; `.env` имеет приоритет.

**Откат:** изменить значение обратно (`gpt-5-mini`, `gpt-4o-mini` и т. п.) и перезапустить сервис.

⚠️ Перед сменой модели рекомендуется офлайн-смоук на 5–10 типовых вопросах — мелкие модели семейства gpt-5 могут возвращать пустые ответы из-за расхода reasoning-токенов.

### 4. Поменять имя/описание бота в Telegram

Через @BotFather (`/setname`, `/setdescription`, `/setabouttext`) или Bot API:

```bash
curl -X POST "https://api.telegram.org/bot<TOKEN>/setMyName" \
  --data-urlencode "name=Чат-Бот ДПО Школа коммуникаций"
```

Перезапуск сервиса при этом не нужен.

### 5. Добавить второго (третьего) админа для уведомлений

1. Узнать **числовой Telegram chat_id** будущего админа.
2. В коде уже зашит цикл по `(ADMIN_CHAT_ID, ADMIN_CHAT_ID_2)`. Если нужен 3-й — добавить переменную `ADMIN_CHAT_ID_3` в `.env`, прочитать её в `bot.py`, включить в цикл (там, где `notify_admin` и `handle_rating`).
3. Перезапустить сервис.

### 6. Получить статистику обращений

CSV-лог: `/opt/bot/questions_log.csv`. Колонки:
`дата_время, user_id, username, имя, фамилия, вопрос, ответ, оценка`.

Скачать: `scp root@206.251.48.91:/opt/bot/questions_log.csv .` и открыть в Excel / pandas.

## Логи и отладка

| Симптом | Где смотреть | Что проверить |
|---|---|---|
| Бот не отвечает в Telegram | `systemctl status faqbot`, `journalctl -u faqbot -n 100` | `Active: failed`? ошибка в логах? |
| Бот стартует, но молчит на вопросы | журнал systemd | `openai.AuthenticationError` → проверить `OPENAI_API_KEY`. `RateLimit` → подождать / поднять лимит на платформе OpenAI. |
| Ответ приходит пустой | журнал + офлайн-тест на той же модели | Возможный расход reasoning-токенов у gpt-5-mini/nano. Сменить модель на `gpt-5.2` (см. п. 3). |
| Ответы со звёздочками `**` | посмотреть последний git-лог | Должна быть применена правка `strip_markdown` + инструкция «без markdown» в `SYSTEM_PROMPT`. |
| Подсказки переформулировок не приходят | журнал | Должна быть строка `Извлечено вопросов из FAQ: N` (N > 0). Если 0 — в FAQ нет строк, начинающихся с `В: `. |
| Сменили `.env`, ничего не поменялось | — | Забыли `systemctl restart faqbot`. systemd читает `EnvironmentFile` только при старте. |
| Уведомления приходят только одному админу | `cat /opt/bot/.env` | `ADMIN_CHAT_ID_2` пустой или второй админ ни разу не писал `/start` боту (Telegram не позволяет ботам инициировать диалог с пользователем, который их не запустил). |
