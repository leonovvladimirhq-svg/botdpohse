# Посредник Telegram Bot API на Cloudflare Workers

Без аренды виртуальной машины. Бот обращается к Worker'у, Worker передаёт запрос
в Telegram и возвращает ответ. Бесплатный тариф, администрировать нечего.

> ✅ **Развёрнут и работает с 23.09.2026:**
> `https://tg-relay-dpo.leonov-vladimir-hq.workers.dev`
> Аккаунт `leonov.vladimir.hq@gmail.com`, Worker `tg-relay-dpo`.
> Telegram-бот `@hse_dpo_faq_bot` поднят через него, в логе `getUpdates … 200 OK`.
> Инструкция ниже нужна для повторного развёртывания или переноса в другой аккаунт.

```
Пользователь Telegram ──► Telegram ◄──HTTPS── Cloudflare Worker (edge)
                                                    ▲ только с IP нашей ВМ
                                                    │ long polling
                              бот faqbot (Yandex Cloud, ru-central1, РФ)
                              база · лог · Yandex AI Studio — остаются в РФ
```

---

## Почему так

С сентября 2026 `api.telegram.org` недоступен с любого российского сервера.
Замер 22.09.2026 на **четырёх** наших ВМ в разных каталогах и подсетях
(`89.169.142.74`, `89.169.146.175`, `111.88.251.184`, `89.169.157.225`) дал
идентичный результат вплоть до одинакового времени отсечки ~5,2 с: `github.com`
отвечает 200, `api.telegram.org` — HTTP 000. Фильтрация идёт по назначению,
а не по нашему адресу, поэтому **перебор IP и аренда новых ВМ бесполезны** —
это проверено, повторять не нужно.

Нужен внешний хоп. Вариант с арендой ВМ в Казахстане заказчик отклонил
22.09.2026, поэтому взят serverless: кода ровно столько же, сервера — ноль.

Доступность платформы с нашей ВМ проверена 22.09.2026: `workers.dev` отвечает
за 0,59 с.

> ⚠️ **Юридическая разница с отклонённым вариантом — для юристов.**
> Казахстан выбирался в аналитической записке не случайно: он в перечне стран
> с адекватной защитой ПДн, передача допускается сразу после уведомления.
> Cloudflare — **американская компания с распределённой сетью**, и заранее
> неизвестно, в какой стране физически отработает конкретный запрос. Это другой
> вопрос, чем Казахстан, и он добавляется к уже открытому пункту про ч. 8 ст. 10
> 149-ФЗ (раздел 7 записки). Решение принимать юристам **до** запуска канала.
> Технически при этом ничего не меняется: Worker ничего не хранит, база и
> обработка остаются в Yandex Cloud (РФ).

## Что нужно

- Аккаунт Cloudflare (бесплатный, регистрация по почте). Свой домен **не нужен** —
  адрес вида `tg-relay-dpo.<ваш-аккаунт>.workers.dev` выдаётся сразу.
- Публичный IP ВМ с ботом: сейчас `89.169.142.74` (сверяйтесь — менялся однажды).
- Числовая часть токена бота до двоеточия (например, из `1234567890:AAF…` это
  `1234567890`) — необязательно, но с ней релей надёжнее.

## Шаг 1. Развернуть Worker

### Вариант А — через веб-консоль (проще, ничего ставить не нужно)

1. **https://dash.cloudflare.com** → *Workers & Pages* → *Create* → *Start with Hello World!* →
   имя `tg-relay-dpo` → *Deploy*.
2. *Edit code* → удалить содержимое редактора → вставить целиком файл
   [`worker.js`](./worker.js) → *Deploy*.
3. *Settings* → *Variables and Secrets* → добавить переменные:

   | Имя | Значение |
   |---|---|
   | `ALLOWED_IPS` | `89.169.142.74` |
   | `ALLOWED_BOT_IDS` | числовая часть токена до двоеточия |

   → *Deploy* ещё раз, чтобы переменные применились.

### Вариант Б — через CLI (воспроизводимо, из этой папки)

```bash
cd relay
# вписать ALLOWED_BOT_IDS в wrangler.toml, проверить ALLOWED_IPS
npx wrangler login
npx wrangler deploy
```

После деплоя консоль покажет адрес вида
`https://tg-relay-dpo.<аккаунт>.workers.dev` — это и есть релей.

> ⚠️ **Грабля первого деплоя.** У аккаунта должно быть зарегистрировано имя
> поддомена `*.workers.dev` — оно выбирается один раз и входит в адрес всех
> Worker'ов. Пока его нет, `wrangler deploy` падает с «could not automatically
> register … as your workers.dev subdomain». Команды для этого в wrangler 4 нет —
> только через консоль: *Compute → Workers*, либо ссылка из текста ошибки.
> У нас имя получилось `leonov-vladimir-hq`.
>
> **Не подключайте репозиторий к Cloudflare через «Create an app» / GitHub** —
> Cloudflare склонирует весь репозиторий, увидит в корне `requirements.txt`
> Telegram-бота, начнёт ставить Python-зависимости и упадёт: `wrangler.toml`
> лежит в `relay/`, а не в корне. Если такой проект уже создан — его можно
> удалить, для работы он не нужен: деплой делается командой из папки `relay/`.

> **Без переменных Worker намеренно не работает** и отвечает 503 с подсказкой.
> Это защита: релей без ограничений — бесплатный прокси к Telegram для любого,
> кто узнает адрес, с любым чужим токеном.

## Шаг 2. Проверить релей

С ВМ бота (не с ноутбука — у него другой IP, он получит 403):

```bash
ssh -i ~/.ssh/yc_faqbot_key yc-user@89.169.142.74
curl -s https://<адрес>.workers.dev/relay-health          # ok
curl -s https://<адрес>.workers.dev/bot<TOKEN>/getMe       # {"ok":true,...}
```

Ожидаемые ответы:

| Ответ | Что значит |
|---|---|
| `ok` на `/relay-health` | Worker жив (токен для этой проверки не нужен) |
| `{"ok":true,…}` на `getMe` | сквозной путь до Telegram работает |
| `403 Доступ запрещён: этот IP…` | запрос не с ВМ бота, либо IP ВМ сменился |
| `403 … этот бот не в списке` | `ALLOWED_BOT_IDS` не совпадает с токеном |
| `503 Релей не настроен` | переменные не заданы или деплой после них не повторён |

## Шаг 3. Подключить бота

На ВМ, в `/opt/faqbot/.env`:

```
TELEGRAM_RELAY_URL=https://<адрес>.workers.dev
```

Адрес — **без пути и без слеша в конце**: `bot<токен>` библиотека допишет сама.

```bash
cd /opt/faqbot && sudo docker compose up -d --build
sudo docker logs -f faqbot
```

В логе должно появиться `Telegram Bot API через релей: https://…` и дальше
`getUpdates … 200 OK`. Бот отвечает в Telegram — готово.

Откат: убрать `TELEGRAM_RELAY_URL` из `.env` и пересоздать контейнер — бот пойдёт
напрямую (сейчас это не работает, но код прежний).

## Лимиты и эксплуатация

- **Бесплатный тариф Cloudflare — 100 000 запросов в сутки.** Бот в режиме long
  polling с таймаутом 10 с даёт ~6 запросов в минуту, то есть **менее 9 000 в
  сутки** вместе с ответами пользователям. Запас десятикратный.
- **Долгие запросы.** Long polling держит соединение открытым; таймаут Telegram
  по умолчанию в библиотеке — 10 с, это заведомо в пределах допустимого для
  Worker'а. Если в логах появятся обрывы `getUpdates` — уменьшить таймаут, а не
  увеличивать.
- **Сменился IP ВМ** (пересоздали машину): поправить `ALLOWED_IPS` и передеплоить.
  Симптом — бот в логах получает 403 на каждый запрос.
- **Логи.** Worker ничего не пишет: ни тел запросов, ни токена. Текущие запросы
  можно посмотреть вживую в консоли Cloudflare (*Workers* → *Logs*), но постоянное
  хранение там не включается.
- **Что видно в коде.** Проверки доступа, список отбрасываемых заголовков и
  передача тела потоком — в [`worker.js`](./worker.js), файл небольшой и
  прокомментирован. Логика проверена оффлайн-тестами (16 случаев: разрешённые
  вызовы, отказы по IP/боту/пути, fail closed, гигиена заголовков).

## Что остаётся за пределами техники

Из аналитической записки, без изменений:

- **Заключение юридической службы по ч. 8 ст. 10 149-ФЗ** (запрет иностранных
  мессенджеров при выполнении гос./муниципального задания; Telegram в перечне) —
  **до** запуска канала. При отрицательном ответе техническое решение не нужно,
  единственным каналом остаётся MAX.
- **Уведомление РКН о трансграничной передаче** — отдельно от уведомления об
  обработке. К перечню стран теперь добавляется юрисдикция Cloudflare (см.
  предупреждение выше).
- **Схема потоков данных** и **политика обработки ПДн** — привести в соответствие
  с фактической архитектурой.
- Зафиксировать: **MAX — основной канал, Telegram — дополнительный.**
