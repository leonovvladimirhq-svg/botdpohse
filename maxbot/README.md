# Чат-Бот ДПО Школа коммуникаций НИУ ВШЭ — версия для MAX

Порт Telegram-бота на Bot API мессенджера **MAX**. Вся продуктовая логика
(база знаний, промпты, модель, логирование, уведомления) перенесена без изменений —
переписан только транспортный слой.

- **Бот в MAX:** «Чат-Бот ДПО Школа Коммуникаций» (`@se14233220_bot`, `user_id` 412305012)
- **Хостинг:** Yandex Cloud, каталог `project2-chatbotdpo`, ВМ `faqbot` (`89.169.142.74`)
- **Каталог на сервере:** `/opt/maxbot`, контейнер `maxbot`

---

## Почему понадобился перенос

Telegram блокируется в РФ, и до бота не могут достучаться **пользователи**.
На стороне сервера Telegram, наоборот, всё ещё работает (в `docker-compose.yml`
Telegram-версии закреплён рабочий IPv4 Bot API), но это не решает проблему аудитории.

MAX-версия развёрнута **рядом** с Telegram-версией, ничего не ломая: два независимых
контейнера на одной ВМ. Telegram-бот можно погасить в любой момент отдельным шагом.

## Чем MAX отличается от Telegram (и что из-за этого изменилось в коде)

1. **Нет reply-клавиатуры.** В MAX есть только inline-кнопки, прикреплённые к сообщению.
   Главное меню и кнопка «◀️ Назад в меню» собраны на inline-кнопках типа `callback`.
2. **Нет `ConversationHandler`.** Состояние диалога (`MENU` / `WAITING_QUESTION` + история)
   хранится в памяти процесса, в словаре `_states`. Как и в Telegram-версии, история
   не переживает рестарт контейнера.
3. **Лимит сообщения 4000 символов** (в Telegram 4096). В коде — `MAX_MSG_LIMIT = 3900`.
4. **Ответ на нажатие кнопки** — это `POST /answers?callback_id=...`; он же редактирует
   сообщение (аналог `edit_message_text`).
5. **`bot_started`** — отдельное событие при открытии диалога с ботом, играет роль
   первого `/start`. Если MAX пришлёт следом ещё и текст `/start`, второе приветствие
   гасится дедупликацией (окно 5 секунд).
6. **ID пользователей другие.** Telegram ID администраторов в MAX не работают.

## ⚠️ Домен API: только `botapi.max.ru`

В документации MAX актуальным называется `platform-api2.max.ru`, но **из Yandex Cloud
он недоступен**:

```
TLSv1.3 (OUT), TLS alert, unknown CA (560)
SSL certificate problem: unable to get local issuer certificate
```

Он отдаёт сертификат российского УЦ, которого нет в стандартном `ca-certificates`
в образе `python:3.11-slim`. `botapi.max.ru` работает со стандартным bundle
и отвечает `200 OK` — на нём и построен бот (`MAX_API_BASE`).

Если MAX когда-нибудь отключит `botapi.max.ru`, есть два пути:
установить в образ корневой сертификат Минцифры РФ, либо задать
`MAX_API_BASE=https://platform-api2.max.ru` вместе с этим сертификатом.

## Структура

```
├── maxbot.py             # Весь код: клиент MAX API, меню, Q&A, логирование
├── FAQ_DPO_HSE_v5.docx   # База знаний
├── requirements.txt
├── Dockerfile
├── docker-compose.yml
├── .env.example
└── data/                 # Том с questions_log.csv
```

Клиент MAX API — класс `MaxBot` в `maxbot.py`. Используются только:
`GET /me`, `PATCH /me`, `GET /updates` (long polling), `POST /messages`,
`POST /answers`, `POST /chats/{chat_id}/actions`.
Внешних SDK нет — только `requests`.

```
YANDEX_API_KEY=       # API-ключ сервисного аккаунта Yandex Cloud
YANDEX_BASE_URL=https://llm.api.cloud.yandex.net/v1
MODEL_URI=gpt://b1gvtru3guuc1oipcs4p/qwen3.6-35b-a3b/latest

DOCUMENT_PATH=FAQ_DPO_HSE_v5.docx
LOG_FILE=/data/questions_log.csv

ADMIN_CHAT_ID=        # MAX user_id, НЕ Telegram!
ADMIN_CHAT_ID_2=
```

### Как заполнить `ADMIN_CHAT_ID`

Telegram-идентификаторы администраторов в MAX недействительны. Порядок:

1. Администратор находит бота в MAX и открывает с ним диалог.
2. Отправляет боту команду `/whoami` — бот ответит его MAX ID.
3. Этот ID вписывается в `.env` на сервере, контейнер перезапускается.

Пока поля пустые, бот работает штатно, но уведомления админам не шлёт
(всё продолжает писаться в CSV).

**Важно:** бот может написать пользователю только после того, как тот сам
начал с ним диалог. Администраторы обязаны хотя бы раз открыть бота.

## Логи и отладка

```bash
sudo docker logs -f maxbot                    # живой лог
sudo docker ps                                # maxbot и faqbot должны быть Up
sudo cat /opt/maxbot/data/questions_log.csv   # вопросы, ответы, оценки
```

Проверка доступности API и токена с сервера:

```bash
curl -s -H "Authorization: $MAX_TOKEN" https://botapi.max.ru/me
```

Типовые ответы API:

| Ответ | Значение |
|---|---|
| `dialog.not.found` (404) | пользователь не открывал диалог с ботом |
| `proto.payload` (400) | некорректное тело запроса |
| `verify.token` (401) | токен передан query-параметром вместо заголовка |

## Ограничения, о которых стоит помнить

- **Long polling** в документации MAX помечен как режим для разработки; для продакшена
  рекомендуются webhooks. Для текущей нагрузки polling работает, но при росте трафика
  или потере событий стоит перейти на `POST /subscriptions` (нужен HTTPS-эндпоинт
  с доверенным сертификатом).
- **Лимит 2 сообщения в секунду** на один диалог. Бот шлёт ответ + вопрос об оценке
  подряд; при очень длинных ответах, разбитых на много частей, возможен `429`.
- Состояние диалогов в памяти — после рестарта пользователи возвращаются в меню.
