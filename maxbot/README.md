# MAX-версия бота

Порт Telegram-бота на Bot API мессенджера **MAX** — основной канал с 2026-09-06.
Продуктовая логика (FAQ, промпт, модель, логи, уведомления) та же, что в `bot.py`;
переписан только транспортный слой. Почему переехали — [docs/DECISIONS.md](../docs/DECISIONS.md),
как обновлять и чинить — [README.md](../README.md).

- **Бот:** «Чат-Бот ДПО Школа Коммуникаций», `@se14233220_bot`, `user_id` 412305012.
- **На сервере:** `/opt/maxbot`, контейнер `maxbot`.
- **Код:** весь в `maxbot.py`; клиент API — класс `MaxBot` на `requests`, без внешних SDK.
- **Переменные:** [`.env.example`](.env.example) — все с пояснениями.

## Чем MAX отличается от Telegram (и что из-за этого в коде)

1. **Нет reply-клавиатуры.** Только inline-кнопки, прикреплённые к сообщению. Главное меню
   и «◀️ Назад в меню» — inline-кнопки типа `callback`.
2. **Нет `ConversationHandler`.** Состояние диалога (`MENU` / `WAITING_QUESTION` + история)
   хранится в памяти процесса, в словаре `_states`; после рестарта пользователи возвращаются в меню.
3. **Лимит сообщения 4000 символов** (в Telegram 4096). В коде `MAX_MSG_LIMIT = 3900`.
4. **Ответ на нажатие кнопки** — `POST /answers?callback_id=...`; он же редактирует сообщение
   (аналог `edit_message_text`).
5. **`bot_started`** — событие при открытии диалога, играет роль первого `/start`. Если MAX
   пришлёт следом ещё и текст `/start`, второе приветствие гасится дедупликацией (окно 5 с).
6. **ID пользователей другие.** Telegram ID администраторов в MAX не работают.
7. **Текст кнопки — не больше 64 символов**, а на телефоне видно только ~26–28. Поэтому
   «❓ Задать вопрос Виртуальному помощнику (24/7)» стала «❓ Задать вопрос помощнику»
   (старую подпись, набранную текстом, бот понимает).
8. **Подсказки «возможно, вы хотели спросить» — кнопки.** Payload — индекс вопроса в
   `FAQ_QUESTIONS` + короткий хеш (`sug:<idx>:<hash>`): текст вопроса в payload не влезает,
   а хеш защищает от ситуации, когда FAQ обновили и под тем же индексом другой вопрос.
   Нажатие отрабатывает как обычный вопрос; оценку после списка подсказок не спрашиваем.
9. **«◀️ Назад в меню» — на каждом последнем сообщении бота.** Кнопки живут только на своём
   сообщении; без этого после оценки пользователь оставался без кнопок.
10. **Бот не может написать первым.** Только тому, кто сам открыл диалог, — в том числе
    администраторам для уведомлений.

## ⚠️ Домен API: только `botapi.max.ru`

Документация MAX называет актуальным `platform-api2.max.ru`, но **из Yandex Cloud он недоступен**:

```
TLSv1.3 (OUT), TLS alert, unknown CA (560)
SSL certificate problem: unable to get local issuer certificate
```

Он отдаёт сертификат российского УЦ, которого нет в стандартном `ca-certificates` образа
`python:3.11-slim`. `botapi.max.ru` работает со стандартным набором сертификатов — на нём
и построен бот (`MAX_API_BASE`). Если MAX отключит `botapi.max.ru`: установить в образ
корневой сертификат Минцифры РФ и задать `MAX_API_BASE=https://platform-api2.max.ru`.

## Какие методы API используются

`GET /me`, `GET /updates` (long polling: `timeout` ≤ 90, `limit`, `marker`),
`POST /messages?user_id=`, `POST /answers?callback_id=`, `POST /chats/{chat_id}/actions`
(`{"action":"typing_on"}`).

`PATCH /me` (установка списка команд) с 2026-09-29 отвечает `404 method.not.found` — MAX,
видимо, убрал метод. Бот пишет в лог предупреждение и работает дальше.

Авторизация — **только заголовком** `Authorization: <token>`. Проверка токена с сервера:

```bash
curl -s -H "Authorization: $MAX_TOKEN" https://botapi.max.ru/me
```

| Ответ API | Значение |
|---|---|
| `dialog.not.found` (404) | Пользователь не открывал диалог с ботом |
| `proto.payload` (400) | Некорректное тело запроса («Can't deserialize body») |
| `verify.token` (401) | Токен передан query-параметром вместо заголовка |
| `method.not.found` (404) | Метода больше нет в API |

Удобно для проверки формы запроса: корректный payload на несуществующего адресата даёт
404 `dialog.not.found`, а сломанный — 400 `proto.payload`.

## Администраторы для уведомлений

1. Администратор находит бота в MAX и открывает диалог.
2. Отправляет боту `/whoami` — бот отвечает его MAX ID.
3. ID вписывается в `ADMIN_CHAT_ID` / `ADMIN_CHAT_ID_2` в `/opt/maxbot/.env`,
   затем `sudo docker compose up -d`.

Пока поля пустые, бот работает штатно, но уведомления не шлёт (в CSV всё пишется).

## Ограничения

- **Long polling** документация MAX называет режимом для разработки; для продакшена советует
  webhooks. Для текущей нагрузки polling работает. При росте трафика — `POST /subscriptions`
  (нужен HTTPS-адрес с доверенным сертификатом).
- **2 сообщения в секунду** на диалог. Бот шлёт ответ + вопрос об оценке подряд; если длинный
  ответ разбит на много частей, возможен `429`.
- Изредка в логе `Ошибка получения обновлений: HTTPSConnectionPool…` — сетевой сбой, бот сам
  повторяет запрос.
